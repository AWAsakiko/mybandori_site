# 一键写入 Vercel 环境变量（使用说明）

这个脚本会读取项目根目录的 `.env.local`，把 6 个环境变量一次性写入 Vercel 项目，
免去在网页上一条一条点「Add New」。

## 前置条件

1. 项目已经在 Vercel 创建（从 GitHub 导入，或 Vercel Drop 创建）。
2. 有 Node.js 环境（脚本优先用 `vercel` 命令，其次 `npx`，最后回退到本机自带的 Node）。
   - 如果都没有：到 https://nodejs.org/ 下载安装 **LTS** 版本，装完重开 PowerShell。

## 第一次使用：浏览器登录（只需一次）

打开 PowerShell，进入项目目录：

```powershell
cd "E:\Web Design\bandori-guide"
npx vercel login
```

浏览器会打开授权页面，点确认即可。
（如果 `npx` 不可用，也可以直接运行脚本时加 `-Login` 参数，让脚本帮你打开登录页。）

## 运行脚本

```powershell
cd "E:\Web Design\bandori-guide"
powershell -ExecutionPolicy Bypass -File .\scripts\setup-vercel-env.ps1
```

脚本会：

1. 读取 `.env.local` 里的 6 个变量（跳过 `REPLACE_WITH` / `CHANGE_ME` 占位符）；
2. 检查 Vercel 登录状态；
3. 关联项目 `mybandori_site`（如果还没关联）；
4. 逐个写入 `production`、`preview`、`development` 三个环境（已存在则覆盖）；
5. 最后列出环境变量清单。

## 常用参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-Project` | `mybandori_site` | Vercel 项目名 |
| `-SiteUrl` | `https://mybandori.icu` | 覆盖 `NEXT_PUBLIC_SITE_URL`（线上用 https） |
| `-Environments` | `production,preview,development` | 写入哪些环境 |
| `-Scope` | 空 | 如果项目在 Team 下，填 team slug |
| `-Login` | 关 | 未登录时自动执行登录 |
| `-DryRun` | 关 | 只打印命令，不实际写入（建议先跑一次） |

示例：

```powershell
# 先看会做什么，不实际写入
powershell -ExecutionPolicy Bypass -File .\scripts\setup-vercel-env.ps1 -DryRun

# Team 项目 + 只写生产环境
powershell -ExecutionPolicy Bypass -File .\scripts\setup-vercel-env.ps1 -Scope my-team -Environments production
```

## 写入完成后

**必须重新部署**才会生效：

Vercel → 项目 → **Deployments** → 最新部署右侧 **⋯ → Redeploy**。

## 常见问题

**提示「关联项目失败」**
- 项目名不对：到 Vercel 项目列表复制准确名称，用 `-Project` 传入；
- 项目还没创建：先到 https://vercel.com/new 导入 `AWAsakiko/mybandori_site`；
- 项目在 Team 下：加 `-Scope 你的team-slug`。

**提示未登录**
- 先运行 `npx vercel login`，或加 `-Login` 参数。

**想确认写入了哪些**
- 脚本最后会执行 `vercel env ls`；
- 也可以到 Vercel → Settings → Environment Variables 查看。

## 安全说明

- 脚本只读取 `.env.local`，不会把值打印到屏幕（只显示变量名和长度）；
- `.env.local` 不会提交到 Git；
- 写入时值会作为命令行参数传给 Vercel CLI，仅在本机进程内可见；
- 如果 `.env.local` 里的 secret key 或密码曾在公开场合暴露，建议在 Vercel 写入后到 Supabase / GitHub 轮换。
